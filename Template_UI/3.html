analytics Platform Overview

SchoolSaaS addresses the fragmentation in educational administration tools by providing a unified, cloud-native platform. It allows multiple educational institutions (tenants) to operate independently on a single shared infrastructure.

The core challenge was ensuring absolute data isolation between tenants while maintaining a single codebase and database schema to optimize operational costs and deployment pipelines.

Multi-tenant Architecture

Implemented logical isolation using a shared database with `TenantId` columns. Leveraged Entity Framework Core Global Query Filters to ensure tenant isolation happens automatically at the DbContext level, preventing accidental cross-tenant data leakage in developer queries.

security

JWT & Refresh Rotation

Built a robust auth flow utilizing short-lived access tokens (15m) alongside sliding-window refresh tokens stored securely in Redis. Implementing rotation ensures compromised tokens are invalidated early, tracking token families to detect reuse anomalies.

Redis + Distributed Caching

Audit Outbox Pattern

To guarantee at-least-once delivery of critical domain events (like user creation or fee processing) without two-phase commits, events are written to an Outbox table in the same transaction as the entity mutation. A background worker periodically processes these to the message bus.

Feature-based Access Control

Moved beyond simple Role-Based Access Control (RBAC) to a granular Claims-based system mapping to specific features. This allows different subscription tiers to dynamically toggle capabilities per tenant without altering the core codebase.

Retrospective & Learnings

01

State vs. Isolation

Managing tenant state dynamically in background processes (where HTTP context is missing) proved challenging. I learned to heavily utilize ambient state patterns and scoped DI containers to securely pass Tenant IDs to background workers without bleeding data.

02

Cache Invalidation Complexities

When dealing with RBAC caching, simple time-based expiration wasn't enough. I implemented event-driven cache invalidation using Redis Pub/Sub, ensuring that when an admin changes a role, the affected user's session cache is instantly flushed across all nodes.
